# 服务器 GPU 空闲自动启动

任务页点击“空闲自动启动”，启用并保存后，应用会在 SSH 服务器上创建独立的 tmux 等待会话。界面确认“服务器 tmux 托管”后，关闭应用、断开 SSH 或关闭这台电脑，服务器仍会继续等待和启动。tmux 的会话独立于连接客户端运行，参见 [tmux 官方说明](https://github.com/tmux/tmux/wiki/Getting-Started)。

监控范围固定为全部 NVIDIA GPU，无需勾选。**任意一张卡**同时满足利用率和显存阈值，并连续达到设定时长，就使用这一张卡启动一次任务。每张卡按 UUID 独立计时；不同卡轮流空闲不会凑成持续空闲。默认连续 60 秒、利用率不超过 5%、已用显存不超过 1024 MiB，均可修改。服务器约每 5 秒采样；一张卡指标未知时，其他正常卡仍可继续计时。

填写服务器上的 Python 解释器绝对路径、登记的脚本入口、工作目录、脚本参数和日志来源。可直接使用虚拟环境的 Python。参数支持引号，不执行 shell 命令。输出追加到登记日志，日志父目录须已存在。服务器自动将选中卡的 UUID 设置为 CUDA_VISIBLE_DEVICES，因此脚本内部使用 CUDA 编号 **0**；不要在参数里继续固定使用原来的物理编号。

每次启用或“重新等待”只启动一次。界面显示候选 GPU 的连续空闲时间、最终使用的 GPU、启动 PID 和结果；“已启动”表示已创建 Python 进程，训练是否正常仍需查看进程和日志。等待期间可展开“在服务器终端查看等待”，复制 tmux attach 命令；使用 Ctrl+B、D 脱离会话，保留等待运行。该功能使用独立的 tmux socket，不接管已有会话。

停用、重新等待、删除任务或修改启动条件时，应用先确认服务器取消旧等待，再保存本地修改。断网时取消无法确认，界面会提示原规则仍可能运行，并保留原配置。取消等待不会结束已经启动的训练进程。电脑退出不会触发取消。

功能仅用于 SSH 服务器，不用于本机 WSL。服务器自身关机、重启或 tmux 等待进程异常退出会停止等待；当前不提供服务器重启后自动恢复。重新连接应用时会查询已有结果，不会悄悄重建已取消、失败或已完成的同一次等待。需要继续时，请检查后点击“重新等待”。

已有的本地等待规则不会因升级自动安装到服务器，需在任务编辑器中重新保存确认。服务器需已安装 tmux 2.1 或更新版本；应用不会自动安装依赖。当前 lab-campus 已核实为 tmux 3.2a。
