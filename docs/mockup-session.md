# 本轮桌面草图：派发记录

日期：2026-10-18。用户已经同意浏览器草图。产品仍为 Windows 独立桌面窗口；这里制作的是使用模拟数据的可丢弃交互原型。

## 本轮顺序与职责

1. 主控启动现有 brainstorming 本地预览服务，绑定本机地址，不连接训练服务器。
2. 主控直接向 GPT-6-luna 子代理发送下面的布局审查提示词，接收建议。
3. 主控向同一个 Luna 子代理发送草图编写提示词；Luna 只写指定的 HTML 文件。
4. 主控用浏览器检查页面、布局切换及关键场景；需要修改时给 Luna 新文件名和具体反馈。
5. 用户查看 A/B 草图，选择布局或提出改动。本轮不安装桌面框架或接入真实训练。

本轮无需用户转发给 Luna；Gemini、DeepSeek 和 Claude 均未参与本轮草图。

## 设计选择

用户后续以文字明确选择 **A**，以该文字答复为最终布局偏好；不再依据浏览器探索点击推断。主题尚未确认。产品设计沿用左侧任务栏、右侧详情与日志的方向。

两个布局使用相同数据和主题，避免把颜色偏好与布局偏好混为一谈。

- A：左侧任务列表，选中任务的详情与日志在右侧，适合持续查看一个训练。
- B：上方多任务表，下方详情与宽日志，适合快速对比多个任务。
- 明暗主题和连接场景均可切换，作为草图互动，不触发任何真实采集。

预览会话存于 `.superpowers/`，已在工作区 `.gitignore` 中排除。会话地址含临时访问凭据，不写入提示词或长期文档。

## 本轮验证结果

Luna 对 v2 的内联 JS 做了 Node 静态语法检查。主控在 Codex 浏览器中实际检查了：A/B 切换、明暗主题、断线保留“上次训练中”、开机补读提示、三个任务切换、无匹配日志筛选及清除、跟随开关、日志收起后再次展开。未替用户点击“选用当前布局”，预览切换事件不视为最终偏好。

1280×800 下无页面横向溢出，浏览器错误/警告记录为空。布局 B 内容较高，需要纵向滚动查看完整日志；这属于供用户比较的布局取舍。草图不验证真实采集、虚拟列表性能、自动增长日志或桌面打包。

桌面尺寸截图存于 `docs/previews/layout-a.jpg` 与 `docs/previews/layout-b.jpg`，交互草图已在 Codex 保留。验证后恢复了浏览器默认视口。
